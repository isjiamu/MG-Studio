# 验收与修正

## 交付硬条件

1. 对应 brief 的实际视频可解码；分辨率、fps、帧数、时长正确。默认有非静音音轨；用户明确静音时，以 `audio.mode:"silent"` 声明，成片必须零音轨。
2. 中文字形正确、无重要文字越界或被遮挡、无缺图和控制面板入镜。
3. 时间轴全覆盖；随机顺序 seek 与新页面结果一致；渲染无 JS/资源错误。
4. 开头、信息密集段、每个转场、结尾可用。不能只检查每镜正中间的漂亮一帧。
5. 科普事实和品牌信息已核对；假设、概念、数据来源清楚。
6. 字体、音乐、图片、声音来源列明。未核实许可的素材不能标为可商用。
7. 数据图形与输入一致；显示单位/期间/来源或“示意数据”；架构端点/方向真实；中间动画值不能冒充观测值。
8. 角色动作/物件遮挡连续，纸纹不压过正文；巨幕按目标宽高比审查，现场投放另需真实播放验证。

## 自动检查的范围

`npm run verify`：正序、逆序、固定种子的打乱顺序和新页面帧哈希；暂停后不再次 seek 的画面稳定性；场景边界附近帧；声明的文字范围。它不检查审美、文字互相遮挡、画面跳变幅度、动效品味或听感。

`npm run check` 在影片工程目录执行，核对当前配置和 render manifest 的声音意图。两种模式都检查 H.264/yuv420p、完整解码、实际帧数/时长/画幅；有声还检查恰好一条 AAC 48 kHz 音轨、音画时长差、LUFS 与 true peak，明确静音则要求零音轨。默认 -18 至 -14 LUFS 与 -1 dBTP 上限是本交付预设，特定平台另行修改目标和检查器。有声意图下缺音轨或静音必须失败，不能事后改意图掩盖错误。

## 视觉检查

- 每镜稳定帧 + 主体运动最强处。核对真实素材已经进入画面，前后遮挡和主体接触正确。至少看一次首帧、末帧。
- 有旁白的说明片查每句入点和关键落点。核对当下该看的节点、数值或部件是否明确，最后一句能否对上稳定的画面结论。
- 每个转场检查 t−0.2、t−0.07、t、t+0.07、t+0.2 等连续位置，按帧率调整。
- 有完整视频能力时以实际速度看一遍，随后回看最差区间；只有静帧能力时如实记录。
- 角色抓取前后分别检查物件轨迹与抓握误差；落脚后检查实际绘制的支撑点漂移；在事件前后采样主体与相机位置。对经过型关键点再看两侧速度，位置连续不代表不会突然停顿。轨迹检查不能代替对自然动作和遮挡的目视判断。
- 粒子从一个形状转为另一个形状时检查中段和落位帧，稳定轮廓应有阅读时间；微字和波纹不能遮住角色或主体轮廓。
- 多画幅各自查看；自动“无越界”不等于构图舒服。
- 循环检查首尾位置、运动方向/速度和音频零交叉/交叉渐变。图像哈希相同只是一个证据。
- 对照 brief 中 2–3 个理解问题，记录画面在哪个时间段提供答案。图表的实际长度、终值、缺测位置与源文件对照；故事检查行动是否真正引起变化。自查证据与真实观众理解测试分别记录。

## 听觉检查

检查节奏、转场声音的峰值、音乐层次、旁白清晰度、是否刺耳/泵动、尾音是否被切。同时比较安静段、展开段与结尾在最终编码音轨中的分段 RMS，确认整体响度处理没有抹平情绪起伏，并核对事件音效的时间。不要强制每种故事达到同一个分段音量差。看波形和 LUFS 无法替代听觉。没有可听工具时写“音轨与响度技术检测通过，听感未人工验收”，把成片提供给用户试听。

二遍响度处理的实际模式读取音频报告 `applied.normalization_type`；`linear=true` 仅是请求，可能回退为 dynamic。报告 `before` / `after` 是测量，不代表实际应用了其中模拟的输出模式。短片 LRA 与分段能量用于诊断，不作为统一审美门槛。

## 修正记录格式

```text
时间码 / 画幅：
可观察的问题：
影响：
修改：
复查证据：
```

先修事实错误、不可读、遮挡和声音缺失，再修连续性与节奏，最后修装饰。每轮选影响最大的 1–3 项。复查通过即交付；不要为了达到自定分数无止境重写。

## 路由复核

应触发：产品细节动画、品牌故事、新品发布、架构流转视频、CSV 数据播报、超宽展会片、机制科普、只有一句想法的手绘短片。分别选择对应资料和表现方式，不要求全部沿用一套几何模板。

不应触发完整制作：只查询一个数据值、只要一张静态架构图、只裁剪已有实拍视频。用户只要分镜时在分镜交付处完成；不要自动扩张为制作整片。

这些是语义复核用例，只有真实跑过的流程才记为行为实测。未调用的外部模型不计入兼容性成绩。
