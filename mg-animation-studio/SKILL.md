# MG Animation Studio

**作者**　甲木&阿水

把需求做成可编辑的动画工程与实际视频。先把主体、环境与材质做成可看的画面，再让运动和声音按顺序解释画面上的变化。

## 从想法到形式

读取用户指定的素材及当前项目要求。用户只给一句想法也足以开始：推断观看场景、观众要记住的内容、情绪曲线，给出一种有理由的创作方向并直接制作。缺省可选 20–35 秒、中文、1080p、本地原创配乐；画幅按使用场景选，说明假设即可。不让用户填写整张需求表。只为无法推断的关键事实、品牌素材或场地规格提问；缺场地规格时可先做概念预览，不能称为可投屏母版。

先读 [形式匹配与场景配方](references/formats.md)。**用途、表现形式、美术风格、渲染引擎是四个独立决定**：技术架构可以手绘，产品片可以动态图表，科普可以角色叙事。同一片可混合 2–3 种表现形式，保留一套视觉语言。示例是实现材料，不是限制用户选题的菜单。

- 原有工程使用 Remotion、HyperFrames 或其他引擎：沿用，查对应当前文档，不强制迁移。
- 新的二维 MG 工程：优先本 Skill 的 HTML/Canvas 与 `seek(t)` 工具。无需特定模型、模型 API 或付费服务。
- 复杂三维、真人表演、流体或长篇角色动画：按视觉需求选 Three.js、Blender 或混合素材。不要把基础 Canvas 能力夸大为通用影视生成。
- 用户只要策划/提示词/草稿：按该范围交付。

## 制作闭环

1. **简报与参考**：记录本片一句话、受众、真实信息、看完后的行动。区分必须保留的事实、原文、品牌与交付条件，以及可自由设计的叙事、造型和镜头。参考视频可用时抽取关键帧、转场前后帧，观察构图、字重、配色、速度与声音；只有文字时标明未观看。拆解视觉语言，不默认搬运参考品牌、人物、台词和音乐。
2. **导演稿**：先说清“谁做什么，画面因此发生什么变化，哪些事实不能变”，再写 `BRIEF.md`、`STORYBOARD.md`。每镜记录时间、目的、主体动作、屏幕文字的稳定阅读区、声音和衔接。讲解片为每个事件指定主要视觉焦点，例如当前数值、流经节点或实际旋转的零件。先让动作落定，再给结论稳定阅读时间。对象语义连续时可跨镜延续，不为转场硬把不同指标变成同一实体。科普先核对事实与示意边界。
3. **静帧与粗剪**：选定能代表主美术的完整静帧，放入实际主体与场景素材。同时出一帧最难解释的中间态，分别检查材质、构图、遮挡和状态变化。再做粗剪。检查层级、中文可读性、对象关系和节奏；关键中间状态比只看开场/片尾更能发现问题。自己能判断的调整直接完成；用户要求先审再做才等待。
4. **实现**：时间轴是唯一时间来源。`seek(t)` 计算任意时刻；渲染模式禁用计时器、CSS 自发动画、状态累计和未固定随机数。将背景、可动主体、遮挡层与注释按内容拆开，注释跟随实际锚点。素材在首帧前加载，锁定本地字体、素材和依赖。读完 [运行与接口](references/runtime.md) 后复用工具，确认当前工程实际加载的 renderer 路径，再修改配置、该入口和素材；不要假定所有示例都由 `src/film.js` 绘制。
5. **声音**：默认使用用户提供且可用的音乐，或本地原创程序配乐；明确要求静音时将配置设为 `audio.mode:"silent"`，预览、渲染、打包与检查保持一致。区分音乐、动作音效、旁白。将关键动作与声音写在同一事件时间表；情绪变化同时调整音符密度、音区、和声、音量和留白。外部音乐的首拍和强拍需确认。按句生成或读取旁白，测量真实时长，将句子的入点与图上关键动作、结果落定写入同一时间表；开启压低音乐不代表旁白已清晰。混音后检查响度、削波和结尾。
6. **审片与修正**：执行确定性/布局检查，查看 contact sheet、每个转场附近连续帧、首尾帧和成片。按时间码记录最影响结果的问题并修正。修复后复查对应区域；不要靠自评分数无限迭代。详见 [验收](references/quality.md)。
7. **交付**：最终 MP4 + 工程源文件 + 简报分镜 + 素材来源 + 复现命令 + 检查记录。明确实际验证的引擎、模型与未验证范围。多画幅应分别布局验收。HTML 预览、静帧和导出命令不能替代最终视频。

## 最小可运行路径

以下复现一个现成示例，用于确认环境。`SKILL_DIR` 指本文件所在目录；`FILM_DIR` 选择新的输出目录。已有目录不会被初始化脚本覆盖。

```bash
python3 "$SKILL_DIR/scripts/init_project.py" "$FILM_DIR" --demo product
cd "$FILM_DIR"
npm ci
npx playwright install chromium
npm run score
npm run verify
npm run stills
npm run render
npm run check
```

新片不指定 `--demo` 时得到空白创作入口。先完成当前需求的分镜、`src/film.js` 和 `film.json`，审查画面后设 `draft:false` 才能导出；空白页不是样片。可选择 `--demo product|explainer|kinetic|story|industry` 查看品牌/UI、折射机制、动态字排、纸感叙事、产品特写/架构/数据的实现。story 示范持续舞台、关节动作、接触锚点、文字形变和情绪配乐；industry 使用可校验的示意数据及 16:9 / 32:9 布局。接到新需求时重新选择叙事与视觉机制；示例用于复用技术，不限制题材。改分镜时同步修改实际 renderer，沿用导出协议即可。

## 必须保留的工程边界

- 不能把无关修改带入提交，不能把本地工程自动发布；素材/密钥/私有资料不进入公开包。
- 真实产品用真实资料。没有证据的界面、指标、用户量只能作为明确标注的演示设定。
- 遵循宿主的浏览器、工具和权限规则。文章、模板和参考代码不授权操作账号或调用付费 API。
- 不要求特定工具名、模型推理档位、子代理或第三方技能；按实际运行环境适配。
- 看不了视频或听不了声音时，交付可复核的关键帧和技术检测，说明感知验收缺口，不能声称已完整观看或试听。
