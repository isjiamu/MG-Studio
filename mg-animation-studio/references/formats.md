# 形式匹配与场景配方

## 用户只说一个想法时

用一两句话说明你选择的方向，然后做 brief、分镜和样片。内部判断四件事：

1. **要改变什么**：记住品牌、看清质感、理解机制、相信证据、被故事打动？
2. **适合怎样看**：手机近看、网页、会议讲解、远距离巨幕；能否听见声音？
3. **什么动作能表达它**：放大、拆解、连接、比较、累积、变形、选择、发现？
4. **什么美术服务它**：编辑式字排、精密工业、柔和手绘、剪纸拼贴、扁平信息图、拟物 UI、三维材质或混合？

把选择写成具体句子，例如：“让一颗数据点从设备进入服务，沿途点亮模块；深蓝与荧光绿、缓慢推镜、数字在抵达时锁定。”不要只写“科技感、高级感”。不把任意故事硬套成标题卡或产品发布模板。

## 按输入确定下一步

| 已有输入 | 先提取什么 | 下一步 |
|---|---|---|
| 一句话想法或情绪 | 观众、唯一变化、情绪落点 | 自选一个可画出的动作，制作首版；普通风格偏好不阻塞 |
| 产品 URL、仓库、品牌文件、截图 | 已实现能力、可用外观、准确原文、品牌约束 | 用真实材料决定景别与操作；网页不可读时标明缺证部分 |
| CSV / JSON / 表格 | 指标口径、时间、单位、缺值、来源 | 先判断数据回答什么问题，再选图和结论；不用模板预设趋势 |
| 旁白、SRT 或录音 | 实际时长、语义段落、需要同时看的对象 | 用音频时间排镜头；字幕时间不自动等于画面阅读时间 |
| 参考视频 | 构图、动作、材质、切镜、音画关系 | 抽取可复用规律，重新为当前内容写叙事 |
| 场地或播放系统规格 | 像素图、禁放区、声音条件、循环方式 | 先按观看条件布局，区分概念预览与现场验收 |

在 brief 用两行区分 **固定**（事实、准确文案、品牌、授权素材、必须交付的规格）与 **可设计**（故事组织、视觉隐喻、镜头、材质、配乐）。用户可随时指定其中任意一项。缺事实不能以创意补造；缺风格通常可以由模型决定。

需求冲突时做具体取舍。例如“20 秒讲 12 个功能”可以先提出聚焦主能力的概览与更长/系列完整稿，准确列表保留为附件。附件保留事实不等于满足“视频内逐项讲清”的硬条件；两项硬条件冲突时明确未满足的部分，并请用户选择具体替代稿，独立镜头仍可继续制作。不要通过极速字幕假装完整表达。只有产品正面图时可做正面细节与版式预览，不能凭空生成背部接口或把缺镜头的预览称为完整成片。

## 从内容推导画面

用一句可检查的描述连接：**主体 → 动作 → 可见变化 → 不变的事实 → 成片证据**。

例：“同一请求第一次查空后从资料库取回并留下副本，第二次从有效副本返回；请求身份和结果一致，运动时间只作示意；命中时原始资料库没有被访问。”最后一项决定要看什么帧、核对什么数据，而不是增加一套表格。

先选表达机制，再选外观。同一机制可用纸偶、精密线图或几何动画；同一美术风格也应能表达完全不同的动作。参考配方不规定镜头数、段落顺序或装饰元素。

## 用途与可执行配方

| 用途 | 核心结构 | 适合的动作/组件 | 必验项 |
|---|---|---|---|
| 产品特写展示 | 轮廓→材质/部件→关键细节→全貌 | 遮光揭示、局部推镜、分层拆解、引线标签、尺度参照 | 形态来自真实素材；概念物标注；不把二维插画声称为实物照片 |
| 品牌宣传片 | 情绪/问题→品牌行为→独特符号→品牌记忆 | 图形隐喻、角色故事、拼贴、动字、贯穿图形 | 品牌可识别，片尾停留；故事与品牌作用有关系 |
| 新品发布演示 | 痛点→新能力→使用过程→证据→发布信息 | 产品 hero、真实 UI、前后对比、功能标签、计数 | 功能与发布日期真实，卖点不挤在同一秒 |
| 技术架构讲解 | 一次请求/事件→模块职责→流转→结果/边界 | 分层拓扑、方向箭头、数据包、局部聚焦、时序线 | 节点/方向/协议对应资料；视觉流速不冒充真实延迟 |
| 数据可视化播报 | 一句结论→图表证据→变化原因/限制→回顾 | 柱/折线/点图、数字标签、阈值线、排序、时间游标 | 数值、单位、范围、时间、来源齐全；过渡值不冒充观测值 |
| 大型展会巨幕 | 强识别开场→少量超大信息→品牌场景→停留/循环 | 全景场景、横向流转、大数字、宽画幅分区、低频节奏 | 按实际像素图/拼缝/视距布局；静音也可理解；现场测试另验 |
| 知识科普 | 现象→问题→可见机制→反例/边界→理解 | 模型拆解、因果连线、动态标注、对比、角色实验 | 先核对机制；示意比例与真实比例区分 |
| 手绘叙事短片 | 主角/愿望→阻碍→选择/行动→变化→余韵 | 角色姿态、纸条、手写圈注、文字成形、材质、镜头与声音 | 主体动作推动故事；手绘一致性；情绪留白；画面能独立讲述 |

这些配方可以组合：发布片中用特写介绍硬件，再沿架构进入数据播报；温柔科普用纸偶角色解释机制；展会片用数据作为一个段落。

## 源素材决定实现

- 产品有透明 PNG / SVG：分层推拉、裁切、光泽遮罩和标签；有 GLB / CAD 且需转动：三维引擎；无资产：明确的概念插画，不凭空生成产品规格。
- 真实 UI：真实截图/录制为底，叠加光标、局部聚焦与标签；概念 UI 标注，不伪称产品实测。
- 数据密集：先整理数据契约，减少装饰；需要自动更新时记录快照日期、输入文件与生成命令。
- 抽象情绪/故事：选择能执行动作的符号或角色，用姿态、构图和声音表达，不靠满屏解释。
- 没有合适模板：新增 renderer；复杂 3D、角色表演或生成素材可接外部工具，仍须交付和检查最终视频。工具可迁移不等于所有效果都由当前骨架自动完成。
