# 模型与宿主兼容性

## 兼容的是生产协议，不是模型效果保证

这套 Skill 使用 Markdown、普通文件、JavaScript、Node、Python 和 FFmpeg。核心流程没有 Anthropic、OpenAI 或国产厂商 SDK、模型 ID、MCP、特定订阅和推理档位依赖。

| 运行条件 | 能完成什么 | 需要怎么适配 |
|---|---|---|
| 有读写文件和 shell 的 coding agent | 创建工程、改代码、渲染和技术检查 | 按 Skill 路径读取；使用宿主实际工具 |
| 另有视觉能力 | 看静帧并修正版式 | 读 contact sheet、转场帧；不能由静帧推断听觉 |
| 另有视频/音频感知能力 | 实际评估连续运动、声音与同步 | 播放/读取成片后记录观察 |
| 只有文本网页聊天 | 输出分镜和代码，不能自行证明渲染成功 | 用户或本地执行器运行 npm/FFmpeg 命令 |
| 小上下文模型 | 分镜逐个生成、局部修订 | 保留共享契约；每次只给相关镜头与错误 |
| 无网络机器 | 已安装依赖时离线渲染 | 事先安装 npm 与 Chromium，字体/素材本地化 |

Qwen、DeepSeek、GLM、MiniMax、Kimi 等若所在宿主提供文件与执行工具，可使用相同文件协议。品牌名不代表某个具体版本已经实测；代码遵循程度、美术能力、中文排版能力和视觉审片能力需要单独评估。

## 安装

将 `mg-animation-studio` 文件夹复制到宿主支持的 Skill 目录，或在项目中显式要求“读取此文件夹的 SKILL.md 并执行”。常见路径因产品版本而异，核对当前宿主文档，不把某目录对所有工具都适用当成事实。

本项目以 `.agents/skills/mg-animation-studio/` 为正文源。可用软链接让本机 Codex 的 `~/.codex/skills/mg-animation-studio` 指向它；其他机器使用完整文件夹/ZIP 即可。纯聊天使用者可以先提供 SKILL.md，再按链接提供必要参考，不必一次塞入所有文档和原始研究资料。

## 多模型实验协议

使用相同 brief、相同本地素材、相同已安装工具；不要把一个模型的成品代码伪装成另一模型独立生成。记录：

- 厂商与精确模型版本、宿主、可用工具、日期。
- 输入内容与修改范围；允许的迭代时间、次数、预算。
- 首次可运行率、修复次数、布局问题、画面审阅、技术检查。
- 最终视频和源文件；成本只有账单可见才报告。

至少比较产品片和机制科普两种不同任务。对多个版本重复抽样才可讨论稳定性。未执行某模型调用时写“接口可迁移、未实测”，不能写“已兼容验证”。

## 把工作交给另一个模型

先核对宿主真正提供的文件、执行、图像、视频、声音能力，不从模型品牌推断工具存在。不要把某平台专用的工具调用格式写进通用 prompt。

最小交接包含：本片目的与固定事实、相关分镜、当前配置、实际入口路径、`seek(t)` 接口、坐标系、相邻镜头的起止状态、允许修改的文件、复现命令和已有错误。只交接本轮所需内容。须沿页面 import、配置分支到最终绘制函数确认路径；例如 `index.html → film.js → cfg.demo='story' → story.js/createStory`。第一层 import 不一定是本轮该改的 renderer，不能把未加载的文件修改当成生效。

代码以真实文件或逐文件完整代码块交付；JSON 用于配置与结构化数据，读取后做本地校验。截断、缺字段、空响应应报告并重生成缺失部分，不以默认值伪装模型输出完整。

纯聊天路径先由执行器取得完整 Skill/工程 ZIP，保留字体、lockfile 与工具，再将相关文本文件提供给模型做局部创作。不要要求文本模型还原二进制字体、猜测未提供的库 API 或重造整个渲染器。模型交付代码，执行器运行并回传真实报错/帧，二者职责在交接中说明。

保留 lockfile，并安装与当前 Playwright 匹配的 Chromium。离线测试分清“已经安装的工程断网可渲染”和“全新机器能离线安装”；npm 缓存命中只证明当前环境。字体须检查声明字体实际加载成功和中文字形，系统字体回退不能当作指定字体可用。

## 低能力模型的恢复顺序

先修语法/缺文件，再修时间轴和字体，再修构图，最后修动效和声音。每轮给具体错误和对应时间码，不用“再高级一点”这种没有操作意义的要求。渲染工具通过以后尽量保持稳定，避免模型把时间轴改回计时器。
