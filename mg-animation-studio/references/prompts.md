# 可迁移的导演提示词

用户不需要提供完整模板；一句想法也可以启动。把方括号替换为已有信息，缺失的普通偏好由模型选择，真实数据与产品事实不能编造。

按任务取其中一段，不要把所有模板串成一条巨型提示词。提示词锁定需要准确的内容，给叙事和美术留下空间；接触、遮挡、流向、文字交接等容易失败的关系，才补充精确约束。

## 一句话启动

```text
用 mg-animation-studio 把“[我的想法]”做成带配乐的动画。
请根据内容选择适合的叙事、视觉风格、镜头和画幅，直接制作可观看的首版。
交付视频、可改工程和实际检查记录。
```

## 放开创作 / 追求高审美与完成度

```text
用 mg-animation-studio 把 [题材/想法] 做成 [时长] 秒的 MG 短片（路由：审美优先 / 平衡）。
先从题材自身的世界观、材质、光影和情绪出发决定视觉方向与最合适的技术栈
（Canvas 2D / DOM+SVG / Three.js WebGL / 分层素材均可），
做出 2–3 张成片质感的风格帧并全分辨率审阅打磨，再完成全片与声画同步配乐。
不套固定模板，自由发挥你的审美上限；核心事实保持真实。
```

## 手绘故事

```text
我想讲一个关于 [人物/物件] 的小故事：[愿望、困境或一句感受]。
请自选合适的手绘或拼贴材料，用姿态、视线、行动和空间关系来讲述。角色的行动推动情节，
先确定“什么因为什么发生改变”，再设计场景和动效。
配乐跟随情绪，不用每次移动都加音效。请做出带音乐的成片和可编辑代码。
```

## 有材料，但不限定风格

```text
把 [材料路径/可访问 URL] 做成 [用途] 动画，观众是 [谁]。
固定内容：[必须准确的事实、原文、产品外观、交付规格]。
可设计内容：[未指定的叙事、美术、镜头与音乐交给你选择]。
先找出最值得被看见的一次变化，用画面直接呈现它。
素材只支持 [已知边界]，不要发明不可见结构或未经证实的能力。
```

## 借鉴参考的表达方式

```text
参考 [视频/关键帧路径] 中的 [希望借鉴的特征]，为 [新内容] 重新设计。
观察构图、材质、角色动作、转场与声音；分别说明看到了什么、哪些只是推测。
保留适合新内容的视觉规律，人物、故事、品牌信息与音乐按本片重新创作。
先做最难的一处动作或转场，再完成全片。
```

## 产品特写

```text
为 [产品与素材路径] 做一个 [时长] 秒特写展示。
观众最该注意的是 [材质/结构/功能细节]。通过景别、局部揭示、引线标签和最后的全貌建立认识。
选用适合素材的二维、三维或混合实现；不要凭空添加外观、功能和性能数字。
```

## 技术架构

```text
把 [文档/节点关系] 做成能看懂的架构动画。
跟踪一次 [请求/事件]，依次说明谁接收、谁处理、谁返回。画清方向与边界。
先核对节点关系，再用数据包移动和局部聚焦解释；没有真实延迟时明确运动速度是示意。
```

## 数据播报

```text
把 [CSV/JSON 文件] 做成 [时长] 秒的数据播报，重点是 [要回答的问题]。
根据真实字段选择图表，给出单位、期间、来源和口径。
数字和图形共用输入；关键值到位后留出阅读时间。缺失数据明确显示，不能编造补全。
```

## 展会巨幕

```text
为 [活动/展会] 做动态视觉，画布 [真实像素宽高]，视距 [距离]，播放系统 [已知条件]。
主题是 [主题]。先用超宽布局和少量大字做预览，重要信息避开 [拼缝/禁放区]。
[有声/静音]；[有结尾/需要循环]。输出按场地方规格检查的测试片与源文件。
若某项规格缺失，先做概念预览并明确现场还要确认的部分。
```

## 完整制作

```text
请使用 mg-animation-studio，完成一支 [时长] 秒的 [用途] MG 动画。

观众：[谁会看，以及他们已经知道什么]
唯一核心信息：[看完应记住的一句话]
内容与证据：[已确认的事实、真实产品页面或资料]
交付：[画幅、分辨率、fps、语言、视频与源文件]
视觉参考：[文件/URL，以及希望借鉴的构图、色彩、节奏]
素材：[Logo、字体、真实截图；缺失时怎样处理]
声音：[音乐文件 / 本地原创程序配乐]；[是否需要旁白]

先用简报和带时间码的分镜确定叙事，再做关键静帧和粗剪。
主视觉对象跨镜头延续，文字有足够稳定阅读时间，动作有清晰的先后和因果。
给各画幅单独排版。新项目使用已有确定性渲染工具，不重新发明导出器。
看实际静帧、转场连续帧和成片，修正最影响结果的问题。
最后交付带声音的 MP4、可修改工程、素材来源、复现命令和真实验收记录。
常规选择自行决定；只有关键事实、素材或授权缺失时提问。
```

## 品牌与产品

```text
为 [产品] 做一支 [20–30] 秒发布片。核心体验是 [动作发生前 → 用户做什么 → 有什么变化]。
使用提供的真实截图、Logo、品牌色；仅有概念时明确标为概念演示。
开头用一个视觉问题吸引注意，中段让真实产品解决它，结尾留下品牌和一个明确动作。
不要为了展示效果添加未经证实的指标、用户量或功能。
让一个品牌图形贯穿关键转场；在最关键操作发生时安排音效。
先检查最复杂的一镜是否看得懂，再完成全片和带配乐导出。
```

## 知识科普

```text
解释 [概念]，观众是 [受众]，时长 [时长]。
只讲清 [一个机制]，先核对事实来源并注明哪些画面是示意。
按“提出疑问 → 观察变化 → 展示因果 → 标出边界 → 一句话回顾”组织。
对象、箭头和颜色含义保持一致。数据、比例、方向和公式从事实生成。
有旁白时先锁实际音频时间；无旁白时减少文字，并留足阅读区间。
动画要直接呈现机制，而不是让几段解释文字依次飞入。
```

## 连续 UI 形变

```text
制作 [时长] 秒的 UI 形变片。状态序列为：[状态及真实内容]。
以同一个容器贯穿：它的尺寸、圆角、层次随任务变化，光标行为解释状态切换。
每个状态写清开始、稳定、离开时间；旧内容先退，新内容在有空间后进入。
拖动阶段的数值直接由光标位置算出，松手后再平滑回弹。
在用户需要循环时设计首尾位置和速度，再检查音频接缝；不要靠取模伪造循环。
```

## 只改一处

```text
保持其余镜头不变。修正 [时间码]：[观察到的问题]。
期望：[具体画面/节奏/声音结果]。
先定位对应场景与参数，局部修改，输出该区间连续帧和预览片段。
确认关联画幅与音画同步仍正常，再重新导出；保留旧版以便比较。
```

## 小上下文或代码能力较弱的模型

```text
先读本片 BRIEF/STORYBOARD 的相关段落、配置与实际加载的 renderer。
本轮只实现 [镜头 ID]，允许修改的文件是 [核实后的实际路径]；已有导出接口保持不变。
输入：时间区间 [x–y]、坐标系/画幅 [说明]、该镜前后状态 [说明]、
不得改变的事实/对象身份 [说明]、本镜需要看见的变化 [说明]。
输出：实际完整文件或明确文件路径的补丁，不能只给省略号。
以绝对时间计算 seek(t)，能乱序跳到任意帧。运行 [本片实际检查命令]，依据错误修复。
无法执行命令时明确说明，并提供我可直接运行的命令。
```

纯聊天环境可加一句：“请交付文件名与完整代码、所需素材清单及本地运行命令；未执行渲染就写未验证，不要声称视频已生成。”不要把长段代码转义塞进一个 JSON 字符串；结构化 JSON 留给配置、时间表和可校验数据。
